# Comprehensive source audit — Street City Online

Date: 2026-10-21
Scope: Rojo project, Luau server and client, world generation, cars, network ownership,
garage, player profile and migration, credit economy, solo races, 3D asset intake,
local static and Studio smoke checks.

**Verdict: NOT approved for public launch.** Code is inspected and committed to
`main`; this is NOT a verified Roblox Studio or live-server playtest. No CI configured.

## Confirmed issues corrected

| Severity | Area | Defect | Remediation |
| --- | --- | --- | --- |
| P0 | Server bootstrap | RaceService.Start waited for GarageNotice created later in GarageMarketplaceService.Start: blocking startup of shop and all remaining smoke checks | Initialize marketplace before racing; static validator now checks ordering |
| P1 | Shop | Notifications could target disconnected players and successful inventory install could be reported as immediate physical update even when car refresh failed | Guard FireClient and distinguish persistent state from live respawn |
| P1 | Asset security | IsA(BasePart) allowed active Seat/VehicleSeat/SpawnLocation subclasses; validators did not reject arbitrary active descendants | Strict allowed ClassNames and total descendant limit; tests reject scripts/remotes/seats |
| P1 | Asset security | Oversized/empty 3D assets or excessive mesh counts could be accepted if content was unbounded | Limit parts, meshes, descendants, dimensions and bounds; manual review is still required |
| P1 | Profiles | Malformed sparse/dictionary operation journals could be silently normalized and lose entries | Reject sparse/non-array journals; negative tests |
| P1 | Car lifecycle | Vehicle factory exception could prevent a player's car-spawn flow | Catch individual spawn creation failures and log; no false success |
| P1 | Driving | Engine invalidation could leave an old suspension force applied | Zero drive, yaw and suspension actuators if specs are rejected |
| P1 | Ownership | Dead occupant could still be used as an authorized remote/physics driver | Validate Humanoid.Health on both control request and physics loop |
| P1 | Tracks/parking | Initial personal parking shared the active race road; only 12 slots | Move parking to z=-200/200 roads, expand to 48 deterministic slots and warn on capacity |
| P2 | Physics perf | RaycastParams allocated each car on every physics Heartbeat | Cache per vehicle; clear cache on despawn |
| P2 | Rojo live sync | Intent to retain dynamically created world/remotes was implicit | Explicitly set $ignoreUnknownInstances for Workspace and ReplicatedStorage |
| P1 | QA | No checks for complete world/remotes at boot or regression in service startup order | Added server-side world assertions and local bootstrap-order check |

## Still open — release blockers, not claimed fixed

### P0 — runtime and deployment
- No Rojo build or Luau compiler/typechecker execution in the available environment.
- No Roblox Studio Server & Clients 2–4 client validation.
- No published private staging place, save-load confirmation or cross-server session lock test.
- No mobile Android frame-time, memory, streaming or actual touch-steering tests.
- No safe migration/rollback drill for persistent V1->V2 profile data.

### P1 — gameplay correctness
- Suspension is a single rigid chassis with four ray probes and a central lift actuator.
  Cosmetic wheels are welded; real independent wheel constraints are absent.
- Model geometry and roads remain placeholders. Roads may clip buildings;
  the seven districts are not complete high-fidelity environments.
- Race reward anti-exploit uses plausibility gates, not an independently validated competitive anti-cheat.
- Persistent purchases can produce uncertain acknowledgments when DataStore connectivity fails;
  future settlement/receipt reconciliation and long-lived transaction log are required for real-money systems.
- Personal parking has a deliberate 48-car cap; set public server size at or below capacity
  and validate slot collision/availability.
- Client UI has a minimal speed/wallet/toast view, not an accessible full mobile garage/shop UI.
- No NPC traffic, PvP racing, complete Cube 4D ingest pipeline, localized UI, moderation
  tooling or production telemetry.

### P2 — scalability/performance
- Four raycasts per vehicle per physics frame, plus server authoritative chassis forces:
  profile in MicroProfiler under target player count.
- World lacks actual LOD / region streaming lifecycle and device budgets.
- Car engine/gearbox handling is a simplified arcade approximation.

## Required acceptance sequence (manual, no CI)
1. Locally run `python3 tools/validate_project.py`.
2. Run `rojo build default.project.json -o StreetCity.rbxlx`; inspect Luau diagnostics.
3. In unpublished Roblox Studio, confirm smoke assertions finish, world and all remotes exist,
   HUD loads and a personal car spawns (sandbox profile is ephemeral).
4. Server & Clients: drive/steer/lights, unauthorized seating, dead driver, disconnect,
   10-minute physics stability and network input timeout.
5. Complete a time trial and verify 650-credit gain; reject teleport and cut-track attempts.
6. Buy a part, install while parked, switch owned vehicles and test insufficient funds/duplicate IDs.
7. In published staging: V1 migration to V2, saved garage selection across rejoin,
   two competing account sessions, ambiguous saves and shutdown/recovery.
8. Profile 12–48 vehicles plus seven districts, client memory/FPS and touch input.
9. Review creator assets manually and verify Cube 4D meshes/material budgets.
10. Obtain explicit owner approval before public publishing; never enable Robux purchases
    until Roblox receipt processing is designed and tested.

**No claim:** these acceptance tests are not marked as passed. A GitHub commit proves source
changes only. No CI/GitHub Actions and no production deployment.
